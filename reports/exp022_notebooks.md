## Owner workflow

- **Colab:** upload the original ZIP to MyDrive, [open the notebook](https://colab.research.google.com/github/bqa100507-spec/SemEval-2027-Task-12---ArtEmotion-28-Subtask-3---Image-Only-Cross-Cultural-Sentiment-Prediction/blob/6da257fc508a4039f8881b7ddb1e7f5068ecca2b/notebooks/EXP022_Colab.ipynb), select a GPU, Run all and authorize Drive. All defaults are ready; one input-path field handles other locations. [Colab runbook](../docs/exp022_colab.md).
- **Kaggle:** import the [Kaggle notebook](../notebooks/EXP022_Kaggle.ipynb) into a private Notebook, attach a private Dataset containing the same ZIP, enable a GPU and Internet, and Run all. The ZIP is detected under `/kaggle/input`; duplicate/missing matches fail safely. No Drive is used. [Kaggle runbook](../docs/exp022_kaggle.md).

Default Run all prepares an isolated Python 3.12.10 / Torch 2.7.1+cu126 / Transformers 4.49.0 environment and the original pinned requirements; validates source, ZIP, bundle and input-manifest hashes; and executes Preflight/Pilot only. Python 3.12.10 is installed with pinned uv 0.9.8, rather than assuming host Python compatibility. The full resolved dependency lock is recorded. Actual child CUDA availability and runtime versions must pass before training. `CUDA_VISIBLE_DEVICES=0` enforces one GPU.

The final summary displays platform/GPU, total/free VRAM, exact Python/Torch/CUDA, Preflight/Pilot PASS or FAIL, numerical parity, BCE/CE adapter gradients and updates, allocated/reserved peaks, paintings/s, epoch times, MiniScreen/Screen forecasts, resource permission and the exact output path. Child tracebacks stay in separate logs; the first actionable failure is displayed. Failed stages cannot inherit a stale saved PASS label. Reused pilot timings are labeled as saved measurements.

`RUN_LONG_TRAINING=False` is fixed in the initial configuration. Run all only registers widgets. Later work requires a stage selection, forecast/budget review, fresh authorization and a button click. Supported stages are Setup / Benchmark, MiniScreen, MiniScreenVerify, Screen and ScreenVerify; the original runner still enforces prerequisites and invalidates decisions after a failed replay. The helper additionally blocks MiniScreen/Screen when the measured full Screen forecast exceeds four GPU-hours. Full CV/final verification are not exposed. No scientific hyperparameters are adjusted based on benchmark or score.

## Persistence, transfer and offline setup

Colab reads local extracted images under `/content`, with artifacts/logs in a dedicated identity-specific Drive directory. Kaggle uses `/kaggle/temp` for inputs/environment and `/kaggle/working` for run outputs and downloadable exports. Session storage alone is not durable: the owner must download/version exports or preserve them as a private Dataset before ending a Kaggle session. Save & Run All executes the safe benchmark; it does not replay interactive training-button clicks.

Exports include only published complete model/stage directories, diagnostics, logs, package lock and replay-attempt records (including failed attempts). Interrupted temporary fits are excluded. Checkpoint ZIPs have SHA receipts. Restore checks the archive, every file, original scientific seals and exact source/package/GPU/driver/runtime identities before copying anything. Existing different artifacts are never overwritten. Different hardware/software gets a separate run; transfer does not authorize mixing fits. Partial current models restart.

Offline Kaggle requires a **separate** private runtime kit and published checksum, in addition to the 705 MB data ZIP. An explicitly authorized online Linux build button packages the pinned helper, full Git bundle, managed relocatable Python, exact dependency wheels and lock. Offline bootstrap verifies the kit/helper SHA; setup verifies every entry and installs with `--no-index --find-links`, without a GitHub/pip network request. This kit-building path is implemented and synthetically exercised; an actual Linux cloud kit has not been produced or installed in this Windows task. It may require several GB of network/storage. No model training is part of packaging.
