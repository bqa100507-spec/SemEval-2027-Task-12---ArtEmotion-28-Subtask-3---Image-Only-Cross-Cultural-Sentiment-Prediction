# Project conventions

- Prioritize reliable ST3 competition Contrast, competitive Macro Log Loss, and reproducible inference. Keep concise records for the system description paper. Treat work on other subtasks, additional data, or research variants as separate tasks.
- Use Python 3.12, the isolated `.venv`, and the pinned organizer and CLIP revisions in `configs/st3.json`. Keep upstream data, artwork, weights, credentials, caches and per-run artifacts outside Git. Commit code, lightweight tests and aggregate findings.
- Use `painting` and `image_name` for identity and group splits. Check disjointness before fitting. By default fit on the full authorized official `split=train` and retain a minimum of five binary-mappable annotations per painting-language pair. Use official Development for performance evaluation and bounded checkpoint, hyperparameter and ensemble selection. Keep its gold out of training gradients, auxiliary targets and inference. Keep hidden Evaluation annotations inaccessible.
- For ST3 inference, use artwork pixels and target language. Use painting IDs and image paths to locate files and join results. Keep captions, art metadata, labels and other languages' responses out of model inputs. Keep all evaluation-phase resources outside the development workflow.
- Keep run configuration, input hashes, versions, seeds and coverage with results. Distinguish measured development metrics, organizer references and future hypotheses. Cite external resources and check organizer rules before introducing them.
- Update [the experiment registry](docs/experiment_registry.md) whenever a competition experiment completes. Update [Project State](docs/project_state.md) in the same commit or PR when the best model, active work, blockers or strategic decisions change. Record the evaluation population, source revision, decision and status of the supporting artifacts.
- Use a new run directory for each controlled experiment. Keep shuffled-image diagnostics separate from submission predictions and restrict grouped cross-validation to original training paintings.
- Default to one complete Kaggle notebook with one authorization, Run All, verified resumable checkpoints and automatic export. Five-fold or nested CV and extensive controls are opt-in. Prioritize Development Cultural Contrast and monitor Macro Log Loss. Every successfully trained competition candidate emits a validated standalone ZIP regardless of score, plus applicable ensemble ZIPs, before any promotion decision. Codabench uploads are owner-operated.
- Before delivering a private Kaggle dataset, check upload-safe names across all archive members. Use short ASCII names with letters, digits, dots, underscores and hyphens. Detect case-insensitive collisions and reserved names. When official artwork paths need a mapping, preserve the logical paths in a checksum-pinned manifest and restore them automatically from either an intact ZIP or Kaggle's extracted dataset. Test both input forms.
- Use `scripts/run_st3.py` for local checks and `python -m pytest -q` from the project root for unit tests. Tests should use small fixtures and run without downloading the dataset or weights. Generate and validate archives locally for manual Codabench upload.
